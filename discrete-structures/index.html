Learn to read logic like a contract.

Your slides cover propositions, connectives, truth tables and translation. Week 2 continues with logical equivalence. This page teaches them in that order. Where I add something that is not on your slides, I label it "Beyond the slides".

Objectives. By the end you can: decide if a sentence is a proposition; use ¬ ∧ ∨ ⊕ → ↔ and build truth tables; translate English into logic; write the converse, inverse and contrapositive; and use precedence and brackets correctly.

Try it. The promise is: "If you get 100% on the final, then you get an A." That is p → q.

Flip the switches. Only one combination breaks the promise. That is the whole idea behind implication, and the rest of the chapter builds on it.

1. Propositions

A proposition is a declarative sentence that is either true or false. It does not have to be true. It only has to have a truth value.

Tap each sentence to see the verdict.

Propositional variables are p, q, r, … The proposition that is always true is T, and the one that is always false is F.

2. The connectives

A compound proposition is built from smaller propositions with connectives. Choose a connective, flip p and q, and watch which row of the table you are in.

Beyond the slides: a quick memory trick. ∧ is picky (needs everything true). ∨ is easygoing (needs one true). ⊕ is the "one or the other, not both" version of ∨.

Inclusive vs exclusive or. "Students who have taken CS202 or Math120 may take this class" allows both, so it is ∨. "Soup or salad comes with this entrée" allows only one, so it is ⊕.

3. Implication

p → q is read "if p, then q". Here p is the hypothesis and q is the conclusion. Using the promise from the top of the page:

  • Got 100% and got an A: promise kept.
  • Got 100% and no A: promise broken. This is the only way to break it.
  • Did not get 100%: the promise says nothing about this case, so it cannot be broken. The implication is true. We call this vacuously true.

So p → q is false in exactly one row: p true and q false. This is why a sentence like "If 1 + 1 = 3, then your grandma wears combat boots" counts as true in logic.

Different ways to say p → q

EnglishMeaning
if p, then q · q if p · q whenever p · p implies qp → q
p is sufficient for qp → q
q is necessary for pp → q
p only if qp → q
q unless ¬pp → q
Biggest trap. "p only if q" means p → q, not q → p. "I pass only if I study" means that passing forces studying: pass → study.

Biconditional

p ↔ q ("p if and only if q") is true when p and q have the same truth value. Try it in the connectives table above. It means the same as (p → q) ∧ (q → p).

4. Converse, inverse, contrapositive

Start from p → q. You can form three related statements.

Look at the columns. The contrapositive matches the original in every row. The converse and inverse do not, although they match each other.

Example. "If it rains, the ground is wet." The converse is "if the ground is wet, it rained", which can be false because a sprinkler might be on. The contrapositive, "if the ground is not wet, it did not rain", is always valid.

Slide example. "It raining is a sufficient condition for my not going to town" is r → ¬t. Converse: if I do not go to town, then it is raining. Inverse: if it is not raining, then I will go to town. Contrapositive: if I go to town, then it is not raining.

5. Truth-table lab

With n variables you need 2n rows, and one column for every sub-expression. The lab does that for you. Type an expression, or use the symbol buttons. Single lowercase letters are variables, and T and F are constants.

The lab also names each result as a tautology, a contradiction or a contingency. Week 2 explains those names and how to compare two statements.

6. Precedence and translation

Precedence

From highest to lowest: ¬, ∧, ∨, →, ↔. So p ∨ q → ¬r means (p ∨ q) → ¬r. If you want p ∨ (q → ¬r), you must write the brackets. The lab above shows you the fully bracketed form of whatever you type.

Translating English

Two steps from your slides: (1) identify the atomic propositions and give each a variable, (2) choose the connectives.

"If I go to Harry's or to the country, I will not go shopping."

p: I go to Harry's. q: I go to the country. r: I go shopping.
(p ∨ q) → ¬r

"You can access the Internet from campus only if you are a computer science major or you are not a freshman."

a: you can access the Internet from campus. c: you are a CS major. f: you are a freshman.
a → (c ∨ ¬f)

"The automated reply cannot be sent when the file system is full."

p: the automated reply can be sent. q: the file system is full.
q → ¬p

Beyond the slides: find the "if / only if / unless" word first. It splits the sentence into hypothesis and conclusion. Then translate each side.

7. Common mistakes

  • Thinking p → q is false when p is false. It is true.
  • Reading "p only if q" as q → p.
  • Claiming the converse or inverse is equivalent to the original. Only the contrapositive is.
  • Forgetting that ∨ is inclusive unless ⊕ is stated.
  • Leaving out brackets when precedence changes the meaning.
  • Skipping rows. Always list all 2n rows systematically.

Two statements, one truth table: are they the same?

Week 2 uses the second half of your Chapter 1 slides: tautologies, logical equivalence, De Morgan's Laws and the key equivalences, then proofs by laws. It builds directly on the connectives from Week 1. Anything I add that is not on your slides is labelled "Beyond the slides".

Start with the equivalence checker. Type two statements, or press an example. It builds the truth table and tells you whether they always agree, and if not, the first row where they differ.

Tip: the symbol buttons type into whichever box you used last. You can also type ASCII: ~ or ! for ¬, & for ∧, | for ∨, -> for →, <-> for ↔, xor for ⊕. Single lowercase letters are variables; T and F are constants.

Objectives. By the end you can: classify a statement as a tautology, contradiction or contingency; show two statements are equivalent (or not) with a truth table; state De Morgan's Laws and name the key equivalences; prove an equivalence with a chain of named laws; and rewrite conditionals as p → q ≡ ¬p ∨ q ≡ ¬q → ¬p.

1. Tautologies, contradictions, contingencies

Once you can build truth tables, look at the final column. Its pattern gives the statement a name.

  • A tautology is always true, like p ∨ ¬p. Every row of the final column is T.
  • A contradiction is always false, like p ∧ ¬p. Every row is F.
  • A contingency is neither: sometimes true, sometimes false, like p.

Your slide's table for p: when p is T, ¬p is F, so p ∨ ¬p is T and p ∧ ¬p is F; the same happens when p is F. "Either it is raining or it is not" can never be false, so it is a tautology.

Classifier

Type any statement. The lab shows its truth table and names it.

2. Logical equivalence

Idea. Two statements that look different can say exactly the same thing. If they are always true together and false together, they are logically equivalent.

Definition (from your slides). Two compound propositions are logically equivalent if p ↔ q is a tautology. We write p ⇔ q or p ≡ q. Equivalently: their columns in a truth table agree in every row.

Slide example. ¬p ∨ q is equivalent to p → q:

Beyond the slides: the checker's "Same?" column is the biconditional from Week 1 in action: a row is "yes" exactly when A ↔ B is true in that row.

3. De Morgan's Laws

Named after Augustus De Morgan (1806 to 1871). They tell you how to push a negation inside brackets.

¬(p ∧ q) ≡ ¬p ∨ ¬q
¬(p ∨ q) ≡ ¬p ∧ ¬q

Easy way to remember. When the ¬ moves inside the brackets, the connective flips: ∧ becomes ∨, and ∨ becomes ∧. Each part gets its own ¬.

In words (beyond the slides). "It is not true that I have both a pen and a ruler" means I am missing the pen or I am missing the ruler. "It is not true that I have a pen or a ruler" means I have neither: no pen and no ruler.

Your slide shows the second law in a truth table:

pq¬p¬qp ∨ q¬(p ∨ q)¬p ∧ ¬q

Trap. ¬(p ∧ q) is not ¬p ∧ ¬q. Forgetting to flip the connective is the most common De Morgan mistake. Test it in the checker: type ¬(p ∧ q) and ¬p ∧ ¬q.

5. Proving equivalences with laws

Truth tables get huge (10 variables means 1,024 rows). Instead, show A ≡ B by writing a chain A ≡ A1 ≡ … ≡ An ≡ B, where each step uses one named law.

Beyond the slides: a strategy for choosing steps. (1) Rewrite → and ↔ using ¬ and ∨. (2) Push negations inward with De Morgan. (3) Regroup so that pairs like p and ¬p sit together. (4) Finish with the negation, identity and domination laws.

Worked example 1 (from your slides). Show that ¬(p ∨ (¬p ∧ q)) is logically equivalent to ¬p ∧ ¬q.

  1. ¬(p ∨ (¬p ∧ q))start
  2. ¬p ∧ ¬(¬p ∧ q)second De Morgan law
  3. ¬p ∧ (¬(¬p) ∨ ¬q)first De Morgan law
  4. ¬p ∧ (p ∨ ¬q)double negation law
  5. (¬p ∧ p) ∨ (¬p ∧ ¬q)second distributive law
  6. F ∨ (¬p ∧ ¬q)negation law (¬p ∧ p ≡ F)
  7. (¬p ∧ ¬q) ∨ Fcommutative law for ∨
  8. ¬p ∧ ¬qidentity law for F

Worked example 2 (from your slides). Show that (p ∧ q) → (p ∨ q) is a tautology.

  1. (p ∧ q) → (p ∨ q)start
  2. ¬(p ∧ q) ∨ (p ∨ q)p → q ≡ ¬p ∨ q (the slide says "by truth table for →")
  3. (¬p ∨ ¬q) ∨ (p ∨ q)first De Morgan law
  4. (¬p ∨ p) ∨ (¬q ∨ q)associative and commutative laws
  5. T ∨ Tnegation law
  6. Tdomination law (or idempotent law)

Reading a proof. At every step ask: which law turned the line above into this line? If you cannot name it, you have not understood the step yet.

6. Common mistakes

  • Pushing ¬ inside brackets without flipping ∧ and ∨.
  • Claiming the converse or inverse is equivalent to p → q. Only the contrapositive is.
  • Concluding "equivalent" after checking only some rows of a truth table.
  • Using a law in a step without being able to name it.
  • Applying a law to only part of a line and forgetting the rest of it.
  • Writing ≡ between statements that are merely similar. Equivalent means equal in every row.
  • Forgetting that T and F are propositions too: p ∧ T ≡ p, but p ∧ F ≡ F.

This page follows your Chapter 2 slides (Section 2.1). You will learn what an algorithm is, how to read pseudocode, then searching, sorting and greedy methods. Anything I add that is not on your slides is labelled "Beyond the slides".

1. What is an algorithm?

Every algorithm begins with a clearly stated problem: a valid input goes in, and the desired output comes out. The first job is to state the problem precisely: what the input is, and what the output must be.

Example: the input is a finite list of integers, and the output is the largest integer in it.

Definition (from your slides). An algorithm is a finite set of precise instructions for performing a computation or for solving a problem.

Easy way to think about it (beyond the slides): an algorithm is like a recipe written so carefully that someone who cannot think, only obey, still gets the right dish. "Add salt to taste" is not precise enough. "Add 1 teaspoon of salt" is.

Three ways to write an algorithm down

  • Structured English: numbered steps in plain sentences.
  • Pseudocode: code-like steps that are not tied to any programming language. This is what we use most.
  • Flowchart: boxes and arrows.

2. Reading pseudocode

Your pseudocode needs only three ideas: assignments, conditional statements and loops, all wrapped in a procedure.

3. Worked example: the maximum of a list

Idea. Keep a "champion so far". Start with the first number. Look at the next number. If it is bigger, it becomes the new champion. Repeat until the list ends.

Structured English

  1. Set the temporary maximum equal to the first integer in the sequence.
  2. Compare the next integer with the temporary maximum. If it is larger, set the temporary maximum equal to this integer.
  3. Repeat the previous step if there are more integers. If not, stop.
  4. When the algorithm stops, the temporary maximum is the largest integer.

Pseudocode, with a for loop and with a while loop

procedure max(a1, a2, …, an: integers)       procedure max(a1, a2, …, an: integers)
max := a1                                      max := a1
for i := 2 to n                                i := 2
    if max < ai then max := ai                while i ≤ n
return max {max is the largest element}              if max < ai then max := ai
                                                   i := i + 1

A procedure only counts as an algorithm if it has these properties.

5. Three kinds of problem

  • Searching: find the position of a particular element in a list.
  • Sorting: put the elements of a list into increasing order.
  • Optimization: find the best (maximum or minimum) value of some quantity over all possible inputs.

The rest of this page takes them in order.

6. Searching

The problem. Locate an element x in a list of distinct elements a1, a2, …, an, or decide that it is not there. The answer is the location i where x = ai, or 0 if x is not in the list. Positions start at 1, so 0 can never be a real position, which is why it safely means "not found".

Our focus is two methods: linear search and binary search.

Linear search

Idea. Look at the first element, then the second, then the third, until you find x or run out of list. It is like scanning a class attendance list from the top to find one name.

procedure linear search(x: integer, a1, a2, …, an: distinct integers)
i := 1
while (i ≤ n and x ≠ ai)
    i := i + 1
if i ≤ n then location := i
else location := 0
return location {location is the subscript of the term that equals x, or 0 if x is not found}

From your slide: x = 30 in (10, 50, 30, 70) gives location 3. x = 40 in the same list gives location 0. Run both:

Trap. The loop stops for two different reasons: x was found, or i went past n. The if i ≤ n afterwards tells you which one happened.

Binary search

Idea. This needs a list already in increasing order. Look at the middle element. If x is bigger, it can only be in the right half. Otherwise it is at the middle or in the left half. Keep halving. It is the "guess my number" game: guessing 50 out of 100 and being told higher or lower.

procedure binary search(x: integer, a1, a2, …, an: increasing integers)
i := 1 {i is the left endpoint of the interval}
j := n {j is the right endpoint of the interval}
while i < j
    m := ⌊(i + j)/2⌋
    if x > am then i := m + 1
    else j := m
if x = ai then location := i
else location := 0
return location

The symbol ⌊ ⌋ is the floor: round down to a whole number. For example ⌊(1 + 16)/2⌋ = ⌊8.5⌋ = 8.

Your slide searches for 19 in a 16-element list. Step through it, and watch the grey cells (outside the interval) fade out.

Why it is fast. Each round throws away about half the remaining elements. That is why the 16-element list took only 4 rounds, and a 1,000-element list would need about 10. Linear search might check all 1,000.
Trap. Binary search gives wrong answers on an unsorted list. The player refuses to run until the list is increasing.

7. Sorting

To sort a list is to put its elements in increasing order. There are many sorting algorithms (binary, insertion, bubble, selection, merge, quick, tournament). Your slides work through two: bubble sort and insertion sort.

Bubble sort

Idea. Make several passes through the list. Whenever two neighbours are in the wrong order, swap them. Big values "bubble" to the right, so after pass 1 the largest is at the end, after pass 2 the two largest are at the end, and so on.

procedure bubblesort(a1, …, an: real numbers with n ≥ 2)
for i := 1 to n − 1
    for j := 1 to n − i
        if aj > aj+1 then interchange aj and aj+1
{a1, …, an is now in increasing order}

Why does the inner loop stop at n − i? After i − 1 passes the last i − 1 elements are already in place, so there is no need to compare them again. Try the slide example (3, 2, 4, 1, 5):

Insertion sort

Idea. Sort a hand of playing cards: pick up the next card and slide it into the right place among the cards you already hold. Your sorted section starts as just the first element and grows by one each round. Your slide notes that insertion sort uses a linear search to find the correct position.

procedure insertion sort(a1, …, an: real numbers with n ≥ 2)
for j := 2 to n
    i := 1
    while aj > ai
        i := i + 1
    m := aj
    for k := 0 to j − i − 1
        aj−k := aj−k−1
    ai := m
{Now a1, …, an is in increasing order}

Read it in three parts: (1) the while finds the position i, (2) m := aj saves the new element, (3) the inner for shifts elements right to make a gap, then ai := m drops the saved value into the gap.

Compare. Bubble sort fixes the right end first. Insertion sort builds a sorted section on the left.

8. Greedy algorithms

An optimization problem asks you to minimize or maximize something over all possible inputs. Examples from your slides: find the route between two cities with the smallest total mileage; encode messages using the fewest bits; connect network nodes using the least fibre.

A greedy algorithm solves such a problem by making the best-looking choice at each step. That does not always produce an optimal solution overall, but often it does. So after you pick a greedy rule, you either prove it is always optimal, or find a counterexample.

Making change

Problem. Make change for n cents with quarters (25), dimes (10), nickels (5) and pennies (1), using the fewest coins. Greedy rule: at each step take the largest coin that does not exceed what is left.

Slide example, n = 67: quarter (left 42), quarter (left 17), dime (left 7), nickel (left 2), penny (left 1), penny (left 0). That is 6 coins.

procedure change(c1, c2, …, cr: values of coins, where c1 > c2 > … > cr; n: a positive integer)
for i := 1 to r
    di := 0 {di counts the coins of denomination ci}
    while n ≥ ci
        di := di + 1 {add a coin of denomination ci}
        n := n − ci
{di counts the coins ci}

Greedy lab

Type any coin values and an amount. The lab runs the greedy algorithm and also searches for the true minimum.

Beyond the slides: Counterexample A (coins 25, 10, 1; amount 30) shows greedy using 25 + five 1s = 6 coins, when three 10s would need only 3. Counterexample B is the same idea with coins 4, 3, 1. So the greedy change algorithm is optimal for US coins, but not for every set of coins. The word "greedy" never means "always right".

9. Common mistakes

  • Mixing up := (assign) and = (test).
  • Starting the loop at the wrong place. In max, max := a1 and the loop starts at i := 2.
  • Forgetting i := i + 1 inside a while loop, so it never ends.

  • In linear search, forgetting that "not found" returns 0.
  • Believing a greedy algorithm is always optimal.
  • Tracing too fast. Write down the variables after every step.

1. What is a relation?

Big picture. A relation says which things are connected to which. "Student s is enrolled in course c", "x divides y" and "x ≤ y" are all relations. In maths we store the connection as a set of ordered pairs.

An ordered pair (a, b) has an order: (1, 2) is not the same pair as (2, 1). The set of all possible pairs from A to B is A × B. A relation just picks some of them.

Definition (from your slides). A binary relation R from a set A to a set B is a subset R ⊆ A × B.

Slide example. Let A = {0, 1, 2} and B = {a, b}. Then R = {(0, a), (0, b), (1, a), (2, b)} is a relation from A to B. As a table, a × means "related":

Relations on a set

When A = B we say R is a relation on A: a subset of A × A. All four properties in this chapter are about relations on a set.

Slide example. Let A = {1, 2, 3, 4} and R = {(a, b) | a divides b}. The pairs are (1,1), (1,2), (1,3), (1,4), (2,2), (2,4), (3,3), (4,4). Press a divides b in the explorer to see this exact relation.

Beyond the slides: the notation a R b is a common shorthand for (a, b) ∈ R. Notice that "(a, b) ∈ R" is a proposition, either true or false, exactly as in Week 1.

2. Reflexive

Idea. Everything is related to itself. Think of "has the same age as": you are always the same age as yourself.

Definition. R is reflexive iff (a, a) ∈ R for every element a ∈ A. Symbolically: ∀x [x ∈ U → (x, x) ∈ R].

How to check. In the grid, the whole diagonal must be filled. Write down every pair (a, a) for the set, then tick each one off. One missing pair is enough to fail.

Slide example. R = {(a, a), (b, b)} on X = {a, b} is reflexive.

Trap. Reflexive depends on the whole set A. R = {(1,1), (2,2)} is reflexive on {1, 2}, but not on {1, 2, 3}, because (3, 3) is missing. Extra pairs never hurt reflexivity.

3. Symmetric and antisymmetric

Symmetric: a two-way street

Idea. If a is related to b, then b is related to a. "Is a classmate of" works that way.

Definition. R is symmetric iff (b, a) ∈ R whenever (a, b) ∈ R. Symbolically: ∀x∀y [(x, y) ∈ R → (y, x) ∈ R].

How to check. For every pair (x, y), look for its reverse (y, x). In the grid, the picture must be a mirror image across the diagonal. A loop (a, a) is its own reverse, so loops never break symmetry.

Slide example. R = {(1,2), (2,1), (3,2), (2,3)} on {1, 2, 3} is symmetric. (The explorer has a button for it.)

Antisymmetric: no two-way streets between different elements

Idea. Two different elements are never related in both directions. "Is at most as tall as" works that way: if you are at most as tall as me and I am at most as tall as you, we must be the same height.

Definition. R is antisymmetric iff for all a, b ∈ A, if (a, b) ∈ R and (b, a) ∈ R then a = b. Symbolically: ∀x∀y [((x, y) ∈ R ∧ (y, x) ∈ R) → x = y].

How to check. Ignore the loops. For every pair (x, y) with x ≠ y, the reverse (y, x) must not be in R.

Slide example. R = {(x, y) ∈ N | x ≤ y} is antisymmetric, because x ≤ y and y ≤ x imply x = y.

Trap. Antisymmetric does not mean "not symmetric". They are separate properties, and a relation can have both, either, or neither:

4. Transitive

Idea. "A friend of a friend is a friend": if you can get from a to b and from b to c, you can get from a to c directly. "Is taller than" works that way.

Definition. R is transitive if whenever (a, b) ∈ R and (b, c) ∈ R then (a, c) ∈ R, for all a, b, c ∈ A. Symbolically: ∀x∀y∀z [((x, y) ∈ R ∧ (y, z) ∈ R) → (x, z) ∈ R].

How to check, step by step.

  1. Take a pair (a, b) in R.
  2. Find every pair that starts with b, say (b, c).
  3. For each one, the shortcut (a, c) must be in R. If it is missing, R is not transitive.
  4. Repeat for every pair in R.

Slide example. R = {(1,2), (2,3), (1,3)} on {1, 2, 3} is transitive. The only chain is (1,2),(2,3), and its shortcut (1,3) is there.

Trap: no chains means transitive. R = {(1,2)} is transitive, because there is no chain to break. So is the empty relation. This is the same idea as Week 1: p → q is true whenever p is false.
Beyond the slides: checking a property is an algorithm, as in Week 3. For example: 
procedure is symmetric(R: a set of pairs)
for each pair (a, b) in R
    if (b, a) is not in R then return false
return true

5. Combining and composing relations

Combining

A relation is a set, so you can combine two relations with set operations: R1 ∪ R2 (in either), R1 ∩ R2 (in both), R1 − R2 (in R1 but not R2) and R2 − R1.

Slide example. R1 = {(1,1), (2,2), (3,3)} and R2 = {(1,1), (1,2), (1,3), (1,4)} give:

Edit the boxes to try your own. Write pairs like (1,2), (2,3).

Composition

Idea. Composition chains two relations into a two-step journey. First take a step with R1, then a step with R2. Whenever that journey is possible from x to z, the pair (x, z) is in the composite.

Definition (from your slides). Let R1 be a relation from A to B, and R2 a relation from B to C. The composition R2 ∘ R1 is a relation from A to C: if (x, y) ∈ R1 and (y, z) ∈ R2, then (x, z) ∈ R2 ∘ R1.

Reading order. R2 ∘ R1 is read right to left: R1 acts first. (The slide's figure labels the answer R2 ∘ R1 = {(b, x), (b, z)}, while the slide's text layer shows R1 ∘ R2. Follow the figure and the definition: first R1, then R2.)

How to compute. For each pair (x, y) in R1, find every pair in R2 that starts with that same y, say (y, z). Each match gives (x, z). The middle element y is used up and does not appear in the answer.

Trap. Do not mix up the order. R2 ∘ R1 means R1 first. Also, the matching element must be the second entry of the R1 pair and the first entry of the R2 pair.

6. Common mistakes

  • Calling a relation reflexive when it has loops only for the elements that appear. Check every element of A.
  • Thinking antisymmetric means "not symmetric". They are different questions.
  • Saying (a, a) breaks antisymmetry. It does not: a = a.
  • Checking only some chains for transitivity. Check every pair against every pair that starts where it ends.
  • Treating (a, b) and (b, a) as the same pair. They are different.
  • Forgetting vacuous truth: with no chains, a relation is transitive.
  • Reading R2 ∘ R1 left to right.

Connections. Every definition above is an implication (Week 1). Antisymmetry has the form (p ∧ q) → r, and its contrapositive says: if x ≠ y then not both (x, y) and (y, x) are in R. Checking a property is an algorithm (Week 3), and next week you will see these properties in matrices and graphs.

3. Equivalence relations

Big picture. An equivalence relation is a precise version of "is the same kind as". "Has the same birthday month as", "lives in the same city as" and "has the same remainder when divided by 3" all sort things into groups of look-alikes.

Definition 1. A relation on a set A is an equivalence relation if it is reflexive, symmetric and transitive.
Definition 2. If a and b are related by an equivalence relation, they are called equivalent, written a ∼ b.

Why these three? Reflexive: everything is the same kind as itself. Symmetric: if a is the same kind as b, then b is the same kind as a. Transitive: if a matches b and b matches c, then a matches c.

Try it. Press "Same remainder mod 3" in the tool at the top. It shows the relation a ∼ b if a and b leave the same remainder when divided by 3 on {1, …, 6}: the matrix, the digraph, and a verdict that it is an equivalence relation, with its classes listed. Then press "a divides b". It fails: which property breaks?

Beyond the slides: the "same remainder mod 3" relation is my example. It is the classic one: a ∼ b exactly when 3 divides a − b.

Equivalence classes

Let A be a nonempty set and ∼ an equivalence relation on A. The equivalence class of a, written [a] and read "bracket a", is the set of all elements of A that are equivalent to a. (The formula did not show in my copy of your slide, so this is the standard definition.) Your slide lists three facts:

  • For each a ∈ A, a ∈ [a]. (Because ∼ is reflexive.)
  • For each a, b ∈ A, a ∼ b if and only if [a] = [b].
  • For each a, b ∈ A, [a] = [b] or [a] ∩ [b] = ∅. Two classes are either identical or completely separate.

In the mod 3 example, [1] = [4] = {1, 4}, [2] = [5] = {2, 5} and [3] = [6] = {3, 6}. Three classes, no overlaps.

Partitions

Definition (from your slides). A partition of a set S is a collection of disjoint nonempty subsets of S that have S as their union. That is, the subsets Ai (i ∈ I) form a partition of S if and only if:
  • Ai ≠ ∅ for every i ∈ I,
  • Ai ∩ Aj = ∅ whenever i ≠ j,
  • and the union of all the Ai is S.

Picture. Cut a cake into pieces: no piece is empty, no two pieces overlap, and together they make the whole cake. The equivalence classes of an equivalence relation on A form a partition of A.

Beyond the slides: the reverse also holds. Every partition of a set gives an equivalence relation: say a ∼ b when a and b lie in the same piece.

  • Reading a matrix with rows and columns swapped. Row = first element.
  • Calling a matrix antisymmetric because it is not symmetric. Test the mirror positions.
  • Forgetting that the diagonal must be all 1s for reflexive.
  • In a digraph, forgetting a loop at one vertex when checking reflexive.

  • Claiming an equivalence relation when one of the three properties fails. Name the pair that breaks it.
  • Listing a class twice. [1] and [4] in the mod 3 example are the same class, {1, 4}.

Logic

Translate a sentence into logic
  1. Name the two simple statements: p and q.
  2. Spot the key word: "only if", "if", "necessary", "sufficient", "unless", "but", "neither … nor", "not both".
  3. Write the connective, then test the row p = T, q = F against the sentence.
EnglishFormula
P only if Q · Q is necessary for P · P is sufficient for Q · whenever P, Qp → q
P if Q · P whenever Qq → p
P unless Q¬q → p
P if and only if Q · necessary and sufficientp ↔ q
P but not Qp ∧ ¬q
neither P nor Q¬p ∧ ¬q

Common slip: reversing "only if" and "if".

Construct a truth table
  1. List the variables and write 2n rows (TTT, TTF, … , FFF).
  2. Add a column for each sub-expression, starting with the innermost brackets and negations.
  3. Fill column by column, not row by row.
  4. The last column is the answer.

Common slip: forgetting precedence (¬ first, then ∧, ∨, →, ↔). Use brackets to be safe.

Tautology, contradiction or contingency
  1. Build the truth table.
  2. All T: tautology. All F: contradiction. Mixed: contingency.

Shortcut: to show a conditional is a tautology, ask whether the hypothesis can be true while the conclusion is false. If never, it is a tautology.

Show a tautology or an equivalence using laws (no truth table)
  1. Rewrite → as ¬ and ∨ using p → q ≡ ¬p ∨ q.
  2. Push negations inward with De Morgan.
  3. Regroup so that p and ¬p sit together (associative, commutative).
  4. Finish with the negation law (p ∨ ¬p ≡ T), then domination or identity.
  5. Write the name of the law beside every line.

Common slip: a line without a named law. Marks are given for the reason.

Verify a law with a truth table
  1. Build one column for each side of the law.
  2. If the two columns agree in all rows, the law is verified.

Algorithms

Properties of an algorithm (the Goldbach-style question)
  1. Go through the properties one at a time: input, output, precision (definiteness), finiteness, correctness, generality.
  2. For each, ask: "what could go wrong with this procedure?"
  3. Then ask which of your answers depend on an unproved fact. If the algorithm's stopping depends on whether a conjecture is true, finiteness cannot be guaranteed.
Linear and binary search steps

Linear: write i, the test x ≠ ai, and the new i at each step, then the location.

Binary: write a table with columns i, j, m, am, and the comparison x > am. Update i := m + 1 or j := m, and stop when i = j. Finally test x = ai.

Common slip: forgetting the floor, or using binary search on an unsorted list.

Sorting: describe or trace

Insertion sort in words: keep the left part sorted; take the next element, find its place among the sorted ones, shift the larger ones right, and drop it in. Repeat until the end.

Bubble sort: repeatedly compare neighbours and swap when out of order; after pass k the k largest are in place at the right.

Write min, max or sum (the "write an algorithm" question)
  1. Start with the first element: min := a1 (or sum := a1).
  2. for i := 2 to n, update with ai.
  3. For min: if min > ai then min := ai. For sum: sum := sum + ai.
  4. return the variable.
Greedy change

Take as many of the largest coin as fit, then move to the next coin with what is left. To see if greedy is optimal, try swapping the largest coin for smaller ones.

Relations

Union, intersection and difference

Treat each relation as a set of pairs. Write both sets, tick which pairs are shared, then combine: ∪ all pairs in either, ∩ shared pairs, R1 − R2 pairs in R1 that are not in R2.

Composition S ∘ R

Make a three-column table: pair (x, y) in R, pairs (y, z) in S that start with the same y, resulting pair (x, z). R is applied first. Remove duplicates.

Relation to matrix, matrix to relation

Rows are first elements, columns second elements. Put 1 where the pair is in R, else 0. To go back, each 1 in row i, column j gives (i, j).

Draw or read a digraph

Each pair (a, b) is an arrow from a to b; (a, a) is a loop. To read one, go vertex by vertex and list every arrow that leaves it.

Reflexive, symmetric (and antisymmetric) from a matrix

Reflexive: whole diagonal is 1. Symmetric: the matrix equals its mirror image. Antisymmetric: no mirrored pair of 1s off the diagonal.

Is it a partition?

Check three things: every subset is nonempty; no element is in two subsets; the union is exactly the whole set. Repeats inside one subset do not matter, and an element not in the set spoils the union.

Equivalence relation from a partition

Two elements are related exactly when they are in the same subset. For each subset, write every ordered pair of its elements (including (a, a)). A subset with k elements gives k × k pairs.

Graphs (see the next section)

In-degree and out-degree

For each vertex count arrows arriving (in) and leaving (out). Parallel arrows count each time; a loop adds 1 to both. The sum of in-degrees equals the sum of out-degrees equals the number of edges.

Adjacency list and adjacency matrix

List: for each vertex, the vertices it has an edge to. Matrix: aij is the number of edges from vertex i to vertex j, with the vertices in the stated order.

Draw a graph from an adjacency matrix

Draw one dot per row. For each entry aij draw that many edges between i and j (undirected: use the entries above the diagonal; directed: draw arrows from i to j). A 1 on the diagonal is a loop.

Dijkstra's shortest path
  1. Distance 0 at the start, ∞ everywhere else.
  2. Finalise the unvisited vertex with the smallest distance.
  3. For each neighbour, new distance = (this distance) + (edge weight). Keep it if smaller.
  4. Repeat until all vertices are finalised, then read paths backwards from the predecessors.

2. Graph basics and tools

Beyond your slides: the Chapter 1 to 3 slides you sent me do not cover graphs, but your tutorial and coursework sheets do. This section follows those questions and the standard definitions, so check it against your lecturer's notes.
  • A graph has vertices and edges. In a directed graph each edge is an arrow from one vertex to another. A multigraph allows several edges between the same two vertices, and a loop is an edge from a vertex to itself.
  • Undirected degree: the number of edge ends at the vertex, so a loop counts 2. The degrees add up to 2 × (number of edges).
  • Directed: in-degree is the number of edges arriving, out-degree the number leaving, and a loop counts 1 for each. Both sums equal the number of edges.
  • Adjacency list: each vertex with the vertices it is joined to. Adjacency matrix: row i, column j holds the number of edges from i to j (for an undirected graph the matrix is symmetric, and a loop gives a 1 on the diagonal).

4. Exam cheat sheet

Logic

  • p → q is false only when p = T and q = F. p → q ≡ ¬p ∨ q ≡ ¬q → ¬p. Converse (q → p) and inverse (¬p → ¬q) are not equivalent to it.
  • De Morgan: ¬(p ∧ q) ≡ ¬p ∨ ¬q, ¬(p ∨ q) ≡ ¬p ∧ ¬q.
  • Laws: identity (p ∧ T ≡ p), domination (p ∨ T ≡ T), idempotent, double negation, negation (p ∨ ¬p ≡ T, p ∧ ¬p ≡ F), commutative, associative, distributive, absorption.
  • Precedence: ¬, ∧, ∨, →, ↔. A truth table with n variables has 2n rows.
  • Tautology: all T. Contradiction: all F. Contingency: mixed.

Algorithms

  • Properties: input, output, definiteness, correctness, finiteness, effectiveness, generality.
  • Linear search: i := 1; while (i ≤ n and x ≠ ai) i := i + 1; location is i or 0.
  • Binary search (sorted list): i := 1, j := n; while i < j: m := ⌊(i + j)/2⌋; if x > am then i := m + 1 else j := m; then test x = ai.
  • Bubble sort: pass i compares j = 1 to n − i. Insertion sort: insert aj into the sorted first j − 1 items.
  • Greedy change: largest coin that fits, repeatedly. Not always optimal (coins 4, 3, 1 and n = 6).

Relations

  • Reflexive: (a, a) for every a. Symmetric: (a, b) gives (b, a). Antisymmetric: (a, b) and (b, a) give a = b. Transitive: (a, b), (b, c) give (a, c).
  • Matrix: mij = 1 iff (ai, bj) ∈ R. Reflexive: diagonal all 1. Symmetric: mirror image. Antisymmetric: mij = 0 or mji = 0 for i ≠ j.
  • Composition S ∘ R: (x, z) when (x, y) ∈ R and (y, z) ∈ S. R acts first.
  • Equivalence relation = reflexive + symmetric + transitive. Classes [a]: either equal or disjoint. Partition: nonempty, disjoint, union is the whole set.

Graphs

  • Undirected: sum of degrees = 2 × edges (loop counts 2). Directed: sum of in-degrees = sum of out-degrees = edges (loop counts 1 each).
  • Adjacency matrix aij = number of edges from i to j. Adjacency list = neighbours of each vertex.
  • Dijkstra: finalise the smallest unvisited distance, update neighbours with (distance + weight) if smaller, repeat.
